# Регламент работы с документацией

> Версия: 1.0 · Обновлено: 2026-08-01

## Цель

Описывает, как ведётся документация компании в этом репозитории.

## Принципы (Docs-as-Code)

1. **Документация — это код.** Она живёт в репозитории, версионируется в git и ревьюится через pull request.
2. **Рядом с кодом.** Техническая документация генерируется из docstrings и не дублируется вручную.
3. **Постепенность.** Каждый проект документируется итеративно: обзор → статус → тех. часть → регламенты.
4. **Доступ.** Сайт публикуется на GitHub Pages; чувствительные страницы защищаются общим паролем.

## Структура репозитория

```
docs/
├── index.md
├── projects/
├── reference/
│   ├── python/
│   └── typescript/
└── wiki/
src/
mcp_server/
.github/workflows/
```

## Шаблон страницы проекта

Каждая страница проекта содержит разделы: заголовок, обзор, статус, тех. документация, регламенты, встречи, ссылки.

## Как добавить проект

1. Скопируйте пример `docs/projects/crm.md` в `docs/projects/<slug>.md`.
2. Заполните разделы.
3. Добавьте страницу в `nav` в `mkdocs.yml`.
4. Добавьте строку в таблицу в `docs/projects/index.md`.
5. Отправьте pull request.
